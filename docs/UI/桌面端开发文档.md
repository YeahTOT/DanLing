# DanLing 桌面端开发文档

本文档记录当前桌面端基础版的开发、运行和打包流程。桌面端实现遵循
`docs/UI/桌面端开发计划.md` 中的路线：Tauri v2 桌面壳 + React/Vite 前端 +
Python FastAPI sidecar。

## 当前结构

```text
desktop/
├─ package.json                 # 前端和 Tauri 命令
├─ src/                         # React/Vite 前端
│  ├─ api/client.ts             # 调用 Python sidecar
│  ├─ pet/                      # 宠物动画和状态展示
│  └─ App.tsx                   # 顶部菜单、配置页、状态页
├─ public/pets/danling/         # 桌宠动画资源
└─ src-tauri/
   ├─ Cargo.toml                # Tauri/Rust 项目
   ├─ tauri.conf.json           # 窗口、打包、图标配置
   ├─ capabilities/default.json # shell 权限
   └─ icons/                    # Linux 打包图标
```

Python sidecar 在主包内：

```text
src/danling/api/
├─ app.py           # FastAPI 路由
├─ main.py          # uvicorn 启动入口
├─ schemas.py       # 桌面端状态展示字段
└─ state_service.py # 读取配置、日志和硬件状态
```

当前版本的 Tauri 包没有内嵌 PyInstaller sidecar。桌面应用运行时会尝试调用系统里的
`danling api` 和 `danling config tui` 命令，因此运行机器上需要能找到 `danling` 命令。

## 环境准备

### Python 环境

项目使用 `uv`。常规开发建议在仓库根目录执行：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv sync --all-extras
```

如果只验证桌面 API，至少需要 web 依赖：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv sync --extra web
```

配置 TUI 需要：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv sync --extra tui
```

### Node 环境

本次验证环境：

```text
node v24.3.0
npm  11.13.0
```

安装前端依赖：

```bash
cd desktop
npm install
```

### Rust/Cargo

Tauri 打包需要 Rust。没有 `cargo` 时可用 rustup 安装：

```bash
curl -L https://sh.rustup.rs -o /tmp/rustup-init.sh
sh /tmp/rustup-init.sh -y --profile minimal
source "$HOME/.cargo/env"
```

本次验证环境：

```text
rustc 1.95.0
cargo 1.95.0
```

### Linux 系统依赖

Ubuntu 22.04 上安装 Tauri 依赖：

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential \
  curl \
  wget \
  file \
  libssl-dev \
  libgtk-3-dev \
  libwebkit2gtk-4.1-dev \
  libayatana-appindicator3-dev \
  librsvg2-dev \
  patchelf
```

如果发行版没有 `libwebkit2gtk-4.1-dev`，再检查是否需要换成对应仓库提供的
`libwebkit2gtk-4.0-dev`。当前 Tauri v2/Linux 构建在 Ubuntu 22.04 上使用
`libwebkit2gtk-4.1-dev` 已验证可用。

## 开发运行

### 1. 启动 Python sidecar

在仓库根目录启动 API：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run danling api --no-hardware
```

默认监听：

```text
http://127.0.0.1:8765
```

检查健康状态：

```bash
curl --noproxy "*" http://127.0.0.1:8765/health
```

检查桌宠状态：

```bash
curl --noproxy "*" http://127.0.0.1:8765/api/state
```

如果仓库根目录的 `danling.yaml` 配了很大的 TensorBoard/训练目录，`/api/state` 可能会比较慢。
开发预览时可以指定一个临时空配置：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run danling api \
  --config /tmp/danling-pet-preview.yaml \
  --no-hardware
```

### 2. 启动 Web 前端

```bash
cd desktop
npm run dev -- --host 127.0.0.1
```

默认地址：

```text
http://127.0.0.1:5173/
```

前端默认访问 `http://127.0.0.1:8765`。如需换 API 地址：

```bash
VITE_DANLING_API=http://127.0.0.1:9000 npm run dev -- --host 127.0.0.1
```

### 3. 启动 Tauri 桌面壳

```bash
cd desktop
source "$HOME/.cargo/env"
npm run tauri -- dev
```

窗口配置位于 `desktop/src-tauri/tauri.conf.json`，当前基础版特性：

- 无边框窗口
- 透明背景
- 置顶
- 不显示在任务栏
- 前端通过 `data-tauri-drag-region` 和 `startDragging()` 支持拖动

## 配置功能

桌面端配置页复用 `danling config tui` 的核心纯函数：

- 手动编辑配置字段
- 自动生成 `baseline_score` / `sota_score`
- 配置默认 `source` 和 `data_path`

对应后端 API：

```text
GET  /api/config
PUT  /api/config
POST /api/config/suggest
```

桌面端菜单中的 `TUI` 按钮会通过 Tauri shell 调用：

```bash
danling config tui
```

这要求运行环境中的 `PATH` 能找到 `danling` 命令。

## 常见问题

### `cargo metadata` 找不到命令

说明 Rust/Cargo 未安装或当前 shell 未加载 cargo 路径。

```bash
source "$HOME/.cargo/env"
cargo --version
```

### 缺少 WebKit/GTK 包

构建报 `webkit2gtk`、`gtk`、`libsoup`、`appindicator` 相关错误时，安装 Linux 依赖：

```bash
sudo apt-get install -y \
  libgtk-3-dev \
  libwebkit2gtk-4.1-dev \
  libayatana-appindicator3-dev \
  librsvg2-dev \
  libssl-dev \
  patchelf
```

### `icon.png is not RGBA`

Tauri 要求应用图标是 RGBA PNG。当前图标来自桌宠基础图并转换为 RGBA。

### `couldn't find a square icon to use as AppImage icon`

AppImage 打包需要标准正方形图标。当前已生成：

```text
desktop/src-tauri/icons/32x32.png
desktop/src-tauri/icons/128x128.png
desktop/src-tauri/icons/128x128@2x.png
desktop/src-tauri/icons/icon.png
```

并在 `desktop/src-tauri/tauri.conf.json` 的 `bundle.icon` 中显式声明。

### 桌面应用打开后无法读取状态

当前包没有内嵌 Python sidecar。确认运行环境能找到 `danling`：

```bash
which danling
danling api --no-hardware
```

如果 `danling` 不在 `PATH`，桌面端无法自动启动 API，也无法调用 `danling config tui`。

### `/api/state` 很慢

检查当前 `danling.yaml` 的 `source` 和 `data_path`。如果指向大型 TensorBoard 目录，
首次扫描会比较慢。开发预览时可以用临时配置启动：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run danling api \
  --config /tmp/danling-pet-preview.yaml \
  --no-hardware
```

## 后续建议

当前基础版已经能编译成 Linux 桌面安装包。下一步建议把 Python sidecar 用 PyInstaller
打成 Tauri sidecar，并在 `tauri.conf.json` 中配置 `bundle.externalBin`，这样安装后的桌面端
不再依赖系统 `PATH` 中已有 `danling` 命令。
